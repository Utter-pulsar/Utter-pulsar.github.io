Crazy OS · native OSAgent system

An OS where the agent is native.

Crazy OS is an operating system experiment built around a native OSAgent. Crazy is not a plug-in beside the desktop; Crazy can operate the OS itself, while the user decides how real system information should be handled, filtered, presented, or directly controlled.

Premise

A native OSAgent operating system.

Crazy OS starts from a direct premise: the agent is not an assistant installed on top of an existing desktop. The system itself is designed as an OSAgent-native OS. Crazy is part of the operating model, with permission to read, reason about, and operate the same real system surfaces the user can see.

The information is not theatrical. Files, app state, time, windows, tasks, settings, and generated surfaces are treated as real operating-system material. What changes is the interaction layer: the user can decide whether that material should appear as a full app, a small partial view, a temporary explanation, or no visible app at all.

Crazy OS is an OS where Crazy can operate everything, but the user remains the one who shapes how the OS is presented, customized, and directly controlled.

The model

Real information, user-defined presentation.

The core idea is not to replace every interface with chat. It is to make the boundary between agent action and direct operation flexible. Sometimes the best interface is a complete app. Sometimes it is only the exact slice of information needed. Sometimes Crazy should process the information and return a result without opening anything. Sometimes the user should ignore Crazy entirely and operate the OS directly.

Demos

Five views of a native Agent OS.

Each clip shows a different relation between the user, Crazy, and the OS: opening app surfaces, operating system state, changing time-based presentation, searching through real context, and revising interfaces after they already exist.

01

Open the surface that fits the task

Crazy can create or open an application surface when the user needs one, instead of forcing every operation into a fixed app-first workflow.

02

Operate the system itself

Crazy can work across files, shortcuts, settings, windows, and visible desktop state because OS operation is part of the native model.

03

Change how information appears

The same real context can be presented differently over time: expanded, reduced, reorganized, or hidden until it matters.

04

Process context without ceremony

Search and interpretation do not always need a full application. Crazy can turn system context into the needed answer or surface.

05

Revise the interface after it exists

Presentation remains user-defined. A surface can keep changing after it appears, because the OS treats interface shape as editable state.

Architecture

A desktop shell for testing OS-native agency.

Crazy OS is currently built with Electron and React as a working prototype of the OSAgent idea. Model configuration lives inside system settings, Crazy sits inside the desktop environment, and generated views are rendered as evolving interface state.

The important boundary is not whether every detail already behaves like a finished commercial operating system. The boundary is whether an OS can make agent operation native: Crazy can act across the system, the user can still operate directly, and the presentation layer can be reshaped around the exact amount of information needed.

Status

A prototype for a native Agent OS.

Crazy OS is still a personal prototype, but the direction is clear: an OS where real information can be operated by Crazy, presented in the form the user chooses, or handled directly by the user without involving the agent at all.
